CalcularRFC

An RFC tax-ID calculator built to Mexico's SAT format — designed so a first-time user gets a correct estimate in under a minute, and so Google finds every page of it.

role

live at
icalcularrfc.mx

The problem

The RFC (Registro Federal de Contribuyentes) is a tax ID every person and business in Mexico needs from the SAT. Working it out by hand from the SAT's naming and date rules is slow and error-prone — most people either get it wrong or give up and wait for an official appointment.

The brief was a tool that removes that friction: enter a name and birth date (or a CURP), get a correctly formatted RFC estimate back immediately, with no account and no data stored.

What I built

  • A Next.js app implementing the SAT's actual naming, date, and homoclave format rules for both persona física and persona moral.
  • A CURP-based shortcut so returning users can generate an RFC without re-entering name and birth-date fields separately.
  • A stateless, no-signup flow — the calculation happens client-side, nothing is persisted on the server.
  • A supporting content structure (how RFCs work, character breakdowns, FAQ) built to answer the actual questions people search for around RFC lookup and validation.

SEO & performance

  • Structured the site around distinct, indexable pages — the calculator, RFC lookup, RFC-with-homoclave, and an about/contact set — each targeting a specific search intent instead of one page trying to rank for everything.
  • Wrote and shipped original Spanish-language content answering the real questions people search around RFC generation, rather than machine-translated boilerplate.
  • Added Open Graph and Twitter card metadata, a canonical URL, and structured FAQ content so answers can surface directly in search.
  • Used Next.js image optimization and component-level code-splitting to keep the calculator interactive quickly on mobile connections, which is where most of this traffic lands.

Outcome

The tool is live and indexed, serving free RFC estimates to the Mexican market with no login and no stored user data — the kind of narrow, well-optimized utility that's built to win a specific set of search terms rather than compete broadly.
